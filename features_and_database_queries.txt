================================================================================
           SHILPIKUNJO (ARTIST HIVE) - FEATURES & DATABASE QUERIES
================================================================================

This document provides a human-readable overview of all functional features in 
the ShilpiKunjo platform along with the SQL queries executed against the database.

================================================================================
1. USER AUTHENTICATION & DASHBOARD PROFILE MANAGEMENT
================================================================================

Feature 1.1: User Login Validation
----------------------------------
Description : Verifies user credentials, retrieves password hash, admin status,
              artist bio, portfolio links, and commission availability.
Location    : server/index.js (Line ~27)
SQL Query   :
  SELECT u.*, a.admin_id, ar.bio, ar.portfolio_links, ar.availability_status
  FROM Users u
  LEFT JOIN Admins a ON u.user_id = a.admin_id
  LEFT JOIN Artists ar ON u.user_id = ar.artist_id
  WHERE (u.username = ? OR u.email = ?);

Feature 1.2: Duplicate Account Prevention on Signup
--------------------------------------------------
Description : Checks whether a username or email is already registered.
Location    : server/index.js (Line ~78)
SQL Query   :
  SELECT user_id FROM Users WHERE username = ? OR email = ?;

Feature 1.3: User Dashboard & Profile Details
----------------------------------------------
Description : Fetches complete profile details for the logged-in user including
              account info, artist profile, and verification flags.
Location    : server/index.js (Line ~130)
SQL Query   :
  SELECT u.user_id, u.username, u.email, u.name, u.phone_number, u.address,
         u.created_at, a.admin_id, ar.bio, ar.portfolio_links, ar.availability_status
  FROM Users u
  LEFT JOIN Admins a ON u.user_id = a.admin_id
  LEFT JOIN Artists ar ON u.user_id = ar.artist_id
  WHERE u.user_id = ?;

Feature 1.4: Artist Skills & Expertise Listing
----------------------------------------------
Description : Retrieves all skill tags (e.g. Digital Painting, 3D Modeling)
              associated with an artist profile.
Location    : server/index.js (Line ~157)
SQL Query   :
  SELECT expertise FROM ArtistExpertise WHERE artist_id = ?;

Feature 1.5: User Portfolio Showcase (Dashboard)
-------------------------------------------------
Description : Retrieves all artworks uploaded by the user, sorted newest first.
Location    : server/index.js (Line ~158)
SQL Query   :
  SELECT * FROM Artworks WHERE artist_id = ? ORDER BY created_at DESC;

Feature 1.6: User Commission Contract History (Dashboard)
----------------------------------------------------------
Description : Retrieves all freelance commission briefs where the user is either
              the client or the assigned artist.
Location    : server/index.js (Line ~159)
SQL Query   :
  SELECT c.*, uc.name as client_name, uc.username as client_username,
         ua.name as artist_name, ua.username as artist_username
  FROM Commissions c
  JOIN Users uc ON c.client_id = uc.user_id
  LEFT JOIN Artists a ON c.artist_id = a.artist_id
  LEFT JOIN Users ua ON a.artist_id = ua.user_id
  WHERE c.artist_id = ? OR c.client_id = ?
  ORDER BY c.created_at DESC;

Feature 1.7: User Contest Submissions History (Dashboard)
----------------------------------------------------------
Description : Retrieves all contest entries submitted by the user along with challenge
              titles and artwork details.
Location    : server/index.js (Line ~171)
SQL Query   :
  SELECT cs.*, ch.title as challenge_title, a.title as art_title, a.media_url
  FROM ChallengeSubmissions cs
  JOIN Challenges ch ON cs.challenge_id = ch.challenge_id
  JOIN Artworks a ON cs.art_id = a.art_id
  WHERE cs.artist_id = ?;

2. MAIN FEED & ARTWORK COMMUNITY SHOWCASE
================================================================================

Feature 2.1: Main Feed Gallery Listing
---------------------------------------
Description : Fetches published artworks for the main feed, including artist details,
              total reaction counts, and comment counts.
Location    : server/index.js (Line ~238)
SQL Query   :
  SELECT a.art_id, a.artist_id, a.title, a.type, a.description, a.media_url,
         a.react_count, a.created_at, u.name as artist_name, u.username as artist_username,
         ar.bio as artist_bio,
         (SELECT COUNT(*) FROM ArtworkComments ac WHERE ac.art_id = a.art_id) as comments_count
  FROM Artworks a
  JOIN Artists ar ON a.artist_id = ar.artist_id
  JOIN Users u ON a.artist_id = u.user_id
  WHERE 1=1
  ORDER BY a.created_at DESC;

Feature 2.2: Single Artwork Ownership & Authorization Check
------------------------------------------------------------
Description : Retrieves single artwork data to verify author ownership before
              allowing edit or delete operations.
Location    : server/index.js (Lines ~317, ~360)
SQL Query   :
  SELECT * FROM Artworks WHERE art_id = ?;

Feature 2.3: User Role Authorization Check
-------------------------------------------
Description : Checks if a user is an administrator or the original author.
Location    : server/index.js (Lines ~323, ~366)
SQL Query   :
  SELECT u.user_id, a.admin_id
  FROM Users u
  LEFT JOIN Admins a ON u.user_id = a.admin_id
  WHERE u.user_id = ?;

Feature 2.4: Reaction / Like Duplicate Check
---------------------------------------------
Description : Verifies if a user has already liked/reacted to a specific artwork.
Location    : server/index.js (Line ~392)
SQL Query   :
  SELECT * FROM ArtworkReactions WHERE user_id = ? AND art_id = ?;

Feature 2.5: Artwork Comments List
----------------------------------
Description : Retrieves user comments for an artwork along with commenter display names.
Location    : server/index.js (Line ~411)
SQL Query   :
  SELECT ac.comment_id, ac.art_id, ac.user_id, ac.comment_text, ac.created_at,
         u.name as user_name, u.username
  FROM ArtworkComments ac
  JOIN Users u ON ac.user_id = u.user_id
  WHERE ac.art_id = ?
  ORDER BY ac.created_at ASC;

3. COURSES & LEARNING PLATFORM
================================================================================

Feature 3.1: Course Catalog Listing
-----------------------------------
Description : Fetches available learning courses with instructor profiles, total
              lesson count, and student enrollment numbers.
Location    : server/index.js (Line ~450)
SQL Query   :
  SELECT c.*, u.name as instructor_name, u.username as instructor_username,
         (SELECT COUNT(*) FROM CourseContent cc WHERE cc.course_id = c.course_id) as lesson_count,
         (SELECT COUNT(*) FROM CourseEnrollments ce WHERE ce.course_id = c.course_id) as student_count
  FROM Courses c
  JOIN Artists ar ON c.instructor_id = ar.artist_id
  JOIN Users u ON c.instructor_id = u.user_id
  WHERE 1=1
  ORDER BY c.created_at DESC;

Feature 3.2: Course Details & Curriculum Lessons
------------------------------------------------
Description : Retrieves detailed course information, instructor bio, and sequential lesson list.
Location    : server/index.js (Lines ~524, ~534)
SQL Queries :
  SELECT c.*, u.name as instructor_name, u.username as instructor_username, ar.bio as instructor_bio
  FROM Courses c
  JOIN Artists ar ON c.instructor_id = ar.artist_id
  JOIN Users u ON c.instructor_id = u.user_id
  WHERE c.course_id = ?;

  SELECT * FROM CourseContent WHERE course_id = ? ORDER BY sequence_order ASC;

Feature 3.3: Course Enrollment Status Check
-------------------------------------------
Description : Checks if a user is already enrolled in a course.
Location    : server/index.js (Line ~551)
SQL Query   :
  SELECT * FROM CourseEnrollments WHERE course_id = ? AND user_id = ?;

4. FREELANCE COMMISSIONS & PRIVATE TASK ACCESS CONTROL
================================================================================

Feature 4.1: Job Board Listing & Privacy Access Filtering
----------------------------------------------------------
Description : Fetches freelance contract briefs. Public briefs ('Requested') are
              visible to all users, while active/completed tasks ('Accepted',
              'In Progress', 'Review', 'Completed') are strictly restricted to
              only the client and the assigned commissioner.
Location    : server/index.js (Line ~566)
SQL Query   :
  SELECT c.*, u.name as client_name, u.username as client_username,
         ua.name as artist_name, ua.username as artist_username
  FROM Commissions c
  JOIN Users u ON c.client_id = u.user_id
  LEFT JOIN Artists a ON c.artist_id = a.artist_id
  LEFT JOIN Users ua ON a.artist_id = ua.user_id
  WHERE 1=1
    AND (c.current_status = 'Requested' OR c.client_id = ? OR c.artist_id = ?)
  ORDER BY c.created_at DESC;

Feature 4.2: Commission Task Access & Status Authorization
------------------------------------------------------------
Description : Verifies task details and ensures only the client or assigned artist
              can modify task status for non-'Requested' commissions.
Location    : server/index.js (Line ~623)
SQL Query   :
  SELECT * FROM Commissions WHERE task_id = ?;


================================================================================
5. ART CHALLENGES, COMPETITIONS & VOTING SYSTEM
================================================================================

Feature 5.1: Art Challenges Listing
------------------------------------
Description : Retrieves themed art competitions with creator names and submission counts.
Location    : server/index.js (Line ~665)
SQL Query   :
  SELECT ch.*, u.name as creator_name,
         (SELECT COUNT(*) FROM ChallengeSubmissions cs WHERE cs.challenge_id = ch.challenge_id) as entry_count
  FROM Challenges ch
  JOIN Users u ON ch.creator_id = u.user_id
  WHERE 1=1
  ORDER BY (ch.status = 'Active') DESC, ch.deadline ASC;

Feature 5.2: Contest Submissions Leaderboard
---------------------------------------------
Description : Fetches all artwork entries for a contest sorted by vote count.
Location    : server/index.js (Line ~703)
SQL Query   :
  SELECT cs.submission_id, cs.challenge_id, cs.art_id, cs.artist_id, cs.vote_count,
         cs.rank, cs.submitted_at, a.title as artwork_title, a.type as artwork_type,
         a.description as artwork_desc, a.media_url, u.name as artist_name,
         u.username as artist_username, ar.bio as artist_bio
  FROM ChallengeSubmissions cs
  JOIN Artworks a ON cs.art_id = a.art_id
  JOIN Artists ar ON cs.artist_id = ar.artist_id
  JOIN Users u ON cs.artist_id = u.user_id
  WHERE cs.challenge_id = ?
  ORDER BY cs.vote_count DESC, cs.submitted_at ASC;

Feature 5.3: User Vote History Tracking (Single-Vote Rule)
-----------------------------------------------------------
Description : Retrieves all submission IDs that the logged-in user has already voted for
              in a specific contest to prevent duplicate voting.
Location    : server/index.js (Line ~714)
SQL Query   :
  SELECT cv.submission_id
  FROM ChallengeVotes cv
  JOIN ChallengeSubmissions cs ON cv.submission_id = cs.submission_id
  WHERE cs.challenge_id = ? AND cv.user_id = ?;

Feature 5.4: Contest Submission Duplicate Check
------------------------------------------------
Description : Checks if an artwork has already been entered into a contest.
Location    : server/index.js (Line ~750)
SQL Query   :
  SELECT submission_id FROM ChallengeSubmissions WHERE challenge_id = ? AND art_id = ?;

Feature 5.5: Self-Voting Prohibition & Duplicate Vote Prevention
-----------------------------------------------------------------
Description : Checks submission details to block contestants from voting for themselves,
              and checks ChallengeVotes to prevent multiple votes by the same user.
Location    : server/index.js (Lines ~765, ~777, ~783)
SQL Queries :
  -- Fetch Submission Author Info:
  SELECT * FROM ChallengeSubmissions WHERE submission_id = ?;

  -- Check Previous User Vote:
  SELECT * FROM ChallengeVotes WHERE submission_id = ? AND user_id = ?;

  -- Record Vote:
  INSERT INTO ChallengeVotes (submission_id, user_id) VALUES (?, ?);

  -- Increment Total Vote Count:
  UPDATE ChallengeSubmissions SET vote_count = vote_count + 1 WHERE submission_id = ?;
